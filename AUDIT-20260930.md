# Audit — md_llm

Audit date: 2026-09-30 · baseline: commit `f478199` **plus the uncommitted working-tree changes** (audited as-is on disk)
Method: 7 parallel read-only review areas (core/sandbox, llm providers, chat, reader/docs, controls/app, autossh/launchers, test suite), followed by main-session verification of every load-bearing claim. No code was modified.

---

## Executive summary

md_llm is a well-engineered, unusually well-documented Streamlit package whose subprocess lifecycle handling, atomic-write discipline, and regression-tested security fixes show real care — but this audit found **three P0 holes, all in security/data-safety seams**: a path-traversal arbitrary-file-write in upload staging, a sandbox that fails to deny the settings file holding plaintext API keys (contradicting its own docstring), and an editor-draft leak that can silently overwrite the wrong file. Behind those sits a systemic theme: the "Hardened sandbox" guarantee silently degrades in four independent ways (settings-file read, full env inheritance, fail-open on profile-write errors, a no-op profile for `workdir=/`). The rest of the findings are P1 correctness bugs with clear fixes (UTF-8 stream corruption, ZCode global-config write path, dead persistence reads, autossh status/ownership gaps) and a test suite that is excellent on plumbing but blind to the HTTP wire layer and the chat UI. None of the problems are architectural; the key-lifecycle design is the one structural weakness worth reworking.

## Findings

Severity: **P0** critical (exploitable or silently destroys data) · **P1** important (real bug users will hit) · **P2** minor/polish. Every P0 and P1 below was independently verified by the main session unless marked *(reviewer-verified)*.

### P0 — critical

**P0-1 · Upload staging path traversal → arbitrary file write — `src/md_llm/app.py:481-488` (app)**
`_stage_new_uploads` writes the uploaded bytes to `_UPLOADS_DIR / u.name` and calls `md_llm.open_in_reader(u.name)` with the client-supplied multipart filename verbatim. Streamlit does not basename-sanitize `UploadedFile.name` server-side, so a crafted request (any host that exposes the server beyond localhost — `server.address`, containers) can submit `name = "../../.zprofile"` and get an arbitrary file write with attacker-controlled bytes. The write happens before/independent of the Reader's path guard. The sibling `_open_query_docs` (`app.py:452-453`) *does* sanitize with `Path(name).name` — the omission is clearly unintended. **Fix:** `safe = Path(u.name).name` (reject empty/`..` results), use it for destination and `open_in_reader`; add a `test_app_staging.py` case with a `../`-style fake upload.

**P0-2 · Sandboxed agents can read and exfiltrate the settings file holding plaintext API keys — `src/md_llm/sandbox.py:182-202` (core/sandbox; cross-verified)**
The profile's read-deny covers only `(subpath "{base_dir}")` plus fixed credential/personal trees. In the bundled app, `base_dir` is `~/.md_llm/uploads` (`app.py:71`) but the settings file is `~/.md_llm/_md_llm_settings.json` (`app.py:51`) — a *sibling outside the denied subpath*. Reads are default-allowed (`(allow default)`, line 162) and `(allow network*)` is explicit (line 220), and the OpenAI-compatible registry persists API keys into that file (`controls.py:340-350`, `chat.py:544`). So a prompt-injected agent can `cat` the settings file and POST the keys out — exactly the exfiltration the module docstring (`sandbox.py:16-19`) claims is impossible ("transcripts, chat history, settings … nothing can be copied out"). The same default-allow leaves `~/.netrc`, `~/.git-credentials`, `~/.npmrc`, `~/.kube`, and shell histories readable. **Fix:** add a read deny for the realpath of `get_core().settings_path` (and ideally those sibling dotfiles) in `seatbelt_profile`, keeping the sandbox re-allow after it; correct the docstring.

**P0-3 · Cross-document editor draft leak can silently overwrite the wrong file — `src/md_llm/reader.py:292-310` + `src/md_llm/docs.py:291-301` (reader/docs; reviewer-verified by AppTest repro)**
`open_in_reader(relpath)` in single-document mode only updates the target and calls `docs.reset_documents()`, which pops 5 registry keys but never the *bare* editor keys. Reproduced: edit `notes.md` (unsaved draft), open `other.md` → the editor renders `notes.md`'s draft under `other.md`'s title, unlocked. If the two files' mtimes match (e.g. batch copies made with `cp -p`), the mtime-conflict dialog does not fire and Save **silently writes A's draft into B's file**. Same root cause: `reset_documents()` also leaves all `__doc__`-suffixed keys, so closing a multi-doc session and re-adding a document resurrects its old conversation, violating the documented invariant at `docs.py:457-464`. **Fix:** in the single-doc branch of `open_in_reader`, when the target changes, pop all bare editor keys (draft, unlocked, lock toggle, base mtime, pending, block index/area, raw-area generations); in `reset_documents`, drop `_drop_doc_keys(rel)` for every open document before popping the registry. Add tests for both paths.

### P1 — important

**P1-1 · Hardened sandbox silently fails open — `src/md_llm/llm.py:1245-1249` (same at 1465, 1798)**
`except OSError: profile_path = None  # degrade to unconfined rather than fail` — a transient profile-write failure (ENOSPC, EMFILE) runs the agent with **no** OS confinement even though Hardened is on (default True), with no warning. This contradicts the fail-closed contract stated at `sandbox.py:233`. Note the catch also can't fire for a missing `sandbox-exec` (that raises `RuntimeError`), so the only realized degrade path is the one that must not proceed. Related: `write_seatbelt_profile` (`sandbox.py:289-293`) leaves the `.sb` temp file behind if `f.write` raises. **Fix:** let the error propagate (fail closed, like the profile-validation path), or at minimum `log_event` + surface a warning; mirror `state._write_text`'s unlink-on-failure.

**P1-2 · Agent subprocesses inherit the full parent environment, bypassing the sandbox's credential denies — `src/md_llm/llm.py:1252-1261` (same at 1468, 1801)**
All three agent `Popen` calls omit `env=`. The Seatbelt profile carefully denies file reads of `~/.ssh`, `~/.aws`, Keychains…, but OpenCode/Cline/ZCode (which auto-approve bash tools) receive the parent environment directly — including `OPENROUTER_API_KEY`/`OPENAI_API_KEY`, which this app itself consumes from env (`chat.py:534`). A prompt-injected model's bash tool can `printenv` and exfiltrate over the allowed network. **Fix:** pass a filtered `env=` dropping the secrets this app consumes (not a blanket `*_API_KEY` strip — OpenCode auth may legitimately come from env per its docstrings).

**P1-3 · `run.sh` unconditional upload purge destroys staged files of a live server — `run.sh:32-35`**
`purge_stale_uploads` runs before the script knows whether a server is already up. The droplet launcher (port 8599) and `run.sh` (default port 8501) share `~/.md_llm/uploads`, and browser-uploaded files exist *only* as the staged copy — so running `run.sh` while the droplet server is in use wipes files its open sessions are reading, then `run.sh` may itself fail to boot into the occupied port. **Fix:** probe the port/health first; purge only immediately before a boot this script performs, or only files older than the running server's start.

**P1-4 · Streaming decoder corrupts multi-byte UTF-8 split across chunks — `src/md_llm/llm.py:319`**
`buf += chunk.decode("utf-8", errors="replace")` per 4096-byte `read1` chunk: a CJK character straddling a chunk boundary (this app's primary content) becomes U+FFFD, silently. Verified empirically by the reviewer. Affects all three HTTP streaming clients. **Fix:** `codecs.getincrementaldecoder("utf-8")("replace")`, or keep a `bytes` buffer and decode complete lines only.

**P1-5 · `save_settings` still uses a predictable `.tmp`, never heals a world-readable file, leaks the temp on failure — `src/md_llm/core.py:92-103`**
`tmp = p + ".tmp"` with plain `open` (1) follows a pre-planted symlink at that fixed name, (2) races concurrent savers (host + panels share one settings file by design), (3) the `except OSError` fallback leaves `settings.json.tmp` on disk forever. Worse, line 97 copies the *existing* file's mode, so a legacy 0644 settings file is re-pinned 0644 forever — the new 0600-on-create fix never heals old deployments of a file whose documented purpose is storing plaintext API keys. `json.dump` raising `TypeError` also escapes the "never crash a render" contract. **Fix:** adopt the `tempfile.mkstemp` + unlink-on-failure + `os.replace` pattern already in `llm._write_json_atomic` and `state._write_text`; clamp the mode to `& 0o600` instead of preserving.

**P1-6 · Env-derived API keys get persisted to disk on every send — `src/md_llm/chat.py:531-548`**
In the OpenAI-compatible branch, `api_key` resolves session → registry → `os.environ["OPENAI_API_KEY"]`, and then `_save_oai_registry_entry(..., api_key=api_key, ...)` unconditionally writes it into the plaintext settings file — persisting a secret the user never typed, two branches below the comment "The API key stays write-only by design — never persisted" (`chat.py:513-514`). Also a read-modify-write of settings on *every* send. **Fix:** pass `api_key=` only when it came from the session widget (or differs from the stored entry).

**P1-7 · Clear/Close during an in-flight stream orphans the worker thread and the running agent — `src/md_llm/chat.py:1742-1745` (also 1636-1641 via `_drop_chat_keys`)**
"Clear conversation" pops `_CHAT_BG_TASK` while the daemon worker is still streaming; the reply is silently lost and — worse for agent providers — the auto-approving CLI keeps running tool calls in the sandbox for up to 600 s with no cancel path (Stop only reads the *active* session's task). Neither button is disabled while `_task` is live. **Fix:** before popping, if the task is live set `task["stop"] = True` and call `llm.kill_agent_proc(task["stop_key"])` (or disable the buttons, like the ✕ buttons do).

**P1-8 · OpenCode stop-with-no-text is misclassified as a normal empty reply — `src/md_llm/llm.py:1319`**
`opencode_chat_stream` never checks the returncode after `proc.wait()` (cline does at 1557, zcode at 1856). A Stop kill produces clean EOF → the generator ends without raising → the stop-handling branch is skipped and the "(empty response…)" placeholder is appended as an assistant turn (and fed back to the model on later sends), contradicting the documented "stays bare for Resend" behavior. The same gap turns a genuine CLI crash into an empty reply. **Fix:** raise `RuntimeError` on nonzero returncode, mirroring the other two agents; the existing kill-suppression path then works unchanged.

**P1-9 · Read failures swallowed: crash on non-UTF-8, silent truncation on unreadable — `src/md_llm/state.py:73-81` (reaches `reader.py:1179, 496-534, 1033`; `docs.py:529`)**
`_read_text` catches only `OSError`: a Latin-1/binary file raises `UnicodeDecodeError` straight through `render_reader` (reviewer-verified); an unreadable-but-directory-writable file returns `""`, indistinguishable from empty — and `_write_text(p, "")` then succeeds, so Save silently truncates the original (reviewer-verified). **Fix:** catch `(OSError, UnicodeDecodeError)`, distinguish failure from empty (return None), disable editor+Save on failed initial read, surface a render error.

**P1-10 · ZCode global-config write path: stale selections rewrite the global config; the error path crashes — `src/md_llm/controls.py:968-980`**
The apply block compares the panel's current selection against the freshly-read config, so a *stale* concrete selection is indistinguishable from a fresh pick: an out-of-band model change (terminal `/model`, another CLI session) is reverted on the next rerun with a "switched globally" toast; two mounted panels fight each other on every render. And when `llm.set_zcode_model` raises (read-only config, disk full), the handler at line 978 writes `st.session_state` after the widget was instantiated → `StreamlitAPIException`, so the friendly error never renders. **Fix:** apply via an `on_change` callback (fires only on real user picks, runs before widgets mount) with a per-panel "last applied" mirror key.

**P1-11 · Last-used OpenAI-compatible endpoint is never restored on a fresh session — `src/md_llm/controls.py:1093-1108`**
`panel_endpoint`/`current_endpoint` are computed from `llm_oai_last_endpoint` but used only to build `options`; the selectbox mounts with no seed, defaulting to `options[0]` — the registry's first-inserted endpoint, not the last used. Registry `{A, B}` with last-used `B` reopens on `A`, and an immediate send goes to endpoint `A` with `A`'s stored key/model. **Fix:** pre-mount seed `st.session_state[endpoint_key] = current_endpoint`, the pattern `_seed_openrouter_last_model` already uses.

**P1-12 · 17 dead persistence reads: several settings silently reset every session — `src/md_llm/controls.py:632, 660, 666, 678, 699, 705, 837, 853, 865, 984, 997, 1114, 1144, 1199, 1251`**
`value=saved_llm.get(f"{p}llm_…")` against keys nothing ever writes (verified by grepping every `save_settings`/`_remember_*` writer): OpenCode/Cline/ZCode workdirs, "Hardened sandbox" checkboxes, attach URL, agent name, custom model/variant names, the Ollama endpoint (`:1199`), and the instruction field (`:1269` region) all silently reset to defaults for host panels while the code reads them back as if remembered. **Fix:** persist them on send (extend the `_remember_*` family) or delete the reads; at minimum fix the Ollama endpoint and instruction fields, whose non-persistence is most user-visible.

**P1-13 · `workdir=/` renders a no-op sandbox profile — `src/md_llm/sandbox.py:273` (with 73-87)**
`os.path.abspath(workdir).rstrip("/") or "/"` puts `(subpath "/")` into the write allow (undoing the blanket write deny) and the trailing read re-allow — with last-match-wins this re-allows every denied tree, i.e. an unconfined run presented as hardened. `normalize_workdir` accepts `/` unchanged. **Fix:** raise `ValueError` in `seatbelt_profile` when the sandbox path is `/` or home itself; regression test next to the quote-injection one.

**P1-14 · `_autossh_status` reports "Tunnel up" for any process on the port — `src/md_llm/autossh.py:196-209`**
On `_is_port_open` it returns the curl verdict without checking an autossh process holds the forward (unlike `_handle_start`, which checks `_tunnel_pids`). With the default `local_port=11434` and a local Ollama installed — the common setup for this app's audience — a fresh install shows a green "Tunnel up (HTTP 200)" with a placeholder host. **Fix:** gate the curl verdict on `_tunnel_pids(spec)` being non-empty; same for `_handle_verify`.

**P1-15 · Daemonized autossh tunnels outlive every owner with no record or reaper — `src/md_llm/autossh.py:212-234` (with `macos/launcher.sh:78-103`)**
`autossh -fN` detaches from both the tracked Popen (exits instantly) and the Streamlit process. Closing the browser GCs the session handle without stopping anything; the droplet watchdog kills only the server — the tunnel pair keeps running (and retrying) until reboot. **Fix:** persist started specs/PIDs under `~/.md_llm` and reap them in the launcher watchdog / on session teardown; make outliving explicit if intended.

## Architecture assessment

**Structure.** The layering is clean and the host seam (`Core`/`init`) is well designed: leaf modules import no Streamlit, panels resolve host facts through `get_core()`, and the provider layer is stdlib-only. The dominant structural weakness is the **hand-rolled session-state key lifecycle**: two parallel namespaces (bare keys vs `__doc__`/per-chat suffixed keys) with bespoke pop-sweeps duplicated across `docs.py`, `chat.py`, and `reader.py`. That one design choice is the root cause of P0-3 (bare keys leak across target switches), the `__doc__`-key resurrection invariant violation, and the relpath-collision sweeps (`doc__a.md`). Relpaths are embedded in key names without escaping or length bounds. Centralizing key registration (a per-document/per-chat key-set with one cleanup entry point, and escaped key components) would eliminate the whole leak family.

**Duplication that has already caused drift.** Three atomic-write implementations of varying quality (`state._write_text` and `llm._write_json_atomic` use mkstemp; `core.save_settings` predates them — P1-5). Three agent-Popen blocks in `llm.py` that have drifted: opencode is missing the returncode check (P1-8) and profile-temp cleanup, cline missing profile-temp cleanup, zcode has both right. These should be consolidated; the drift pattern is the evidence.

**Secrets posture.** Plaintext keys in settings.json are documented and deliberate (0600 on create), but the egress surface is not owned by anything: the sandbox doesn't deny the settings file (P0-2), agent children inherit the full env (P1-2), env-derived keys get written to disk (P1-6), and legacy files stay world-readable (P1-5). A single "credential egress" pass — one place that decides what reads keys, what persists them, what the sandbox denies, and what children inherit — would close this class.

**Dependencies & supply chain.** Minimal risk: one runtime dependency (streamlit), stdlib HTTP, no SDKs. The declared floor (`streamlit>=1.44`) is below what the app's CSS/staging assumes (1.58) — cosmetic but worth reconciling. ZCode's model switch rewrites the user's global `~/.zcode/cli/config.json` by design (documented); P1-10 is about unintended writes, not the mechanism.

**Main risks.** (1) The sandbox's security claims exceed its enforcement in four ways (P0-2, P1-1, P1-2, P1-13) — users will trust the Hardened toggle. (2) Silent data loss paths: P0-3 (wrong-file overwrite), P1-3 (upload purge), P1-9 (unreadable-file truncation). (3) The untested HTTP wire layer, which carries the app's default providers.
